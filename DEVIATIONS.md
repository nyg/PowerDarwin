# Deviations

Every difference from Apple's published sources and build environment, one row each.

| ID | Project | Kind | Change | Error it fixes | Upstream |
|---|---|---|---|---|---|
| D1 | all | `build-env` | Each source tarball from Apple's GitHub is unpacked and its top folder renamed from `<project>-<project>-<version>` to `<project>-<version>`, then placed in the build folder's `Sources/`, where darwinbuild takes a plain folder. Contents unchanged. | darwinbuild looks for `Sources/<project>-<version>`; GitHub names the folder after repo and tag. | none |
| D2 | darwinbuild | `bitrot` | The nine Darwin 9 build lists are copied into the build folder's `.build/` before `darwinbuild -init`, which then finds them instead of downloading. darwinbuild itself is unchanged (`Darwin9` branch at `4848b7f`). | The default list site `svn.macosforge.org` no longer exists. | none |
| D3 | Roots | `build-env` | Where archive.org has no Root at a project's 9L30 version, the build environment gets the Root of the nearest earlier build (`older` in `manifest/9L30-roots-used.tsv`), as darwinbuild itself does. Bootstrap only: those projects are then built from source. | darwinbuild stops with `could not find root`. | none |
| D4 | file_cmds | `build-env` | The OpenSSL 46.11 Root is unpacked into the build environment before building file_cmds: libmd's headers include `<openssl/*.h>`, and file_cmds' dependency list lacks OpenSSL. | `/usr/local/include/md5.h:5:25: error: openssl/md5.h: No such file or directory` | none |
| D5 | shell_cmds | `build-env` | launchd's headers are built from source with `darwinbuild -headers -target=launchd_libs launchd_libs` and copied to `Headers/launchd/launchd-258.25.hdrs~1`, so shell_cmds' `launchd` header dependency finds them. darwinbuild passes the build list's target only for `install`, and archive.org has no `launchd.hdrs`. | `nohup.c:60:19: error: vproc.h: No such file or directory` | none |
| D6 | all | `build-env` | [env/arch](env/arch), which prints `ppc`, replaces the build environment's `/usr/bin/arch`. system_cmds' Root ships it as a `uname -m` script, which prints `Power Macintosh` on PowerPC and breaks `mig`. Until system_cmds is built from source. | `gcc-4.0: Invalid arch name : Power` | none |
| D7 | all | `build-env` | darwinbuild copies the host's `dsymutil` (Xcode 3.1.4, `dwarfutils-70`) into the build environment, where it crashes on every binary; on the host it works. The copy is renamed `dsymutil.real` and [env/dsymutil](env/dsymutil) takes its place: it runs the real one and, if that fails, puts a copy of the input binary (thinned to `--arch`) where the DWARF file would be, so later steps that copy or `lipo` it still work, and exits 0. Only the separate debug-symbol bundles are affected, never the built binaries. | xnu: `Bus error /usr/bin/dsymutil --arch=ppc …/mach_kernel.sys`, `make[2]: *** [do_build_mach_kernel] Error 138`; with an empty `.dSYM`, `lipo: can't open replacement file: …/mach_kernel.sys.dSYM/./Contents/Resources/DWARF//mach_kernel.sys` | none |

Kinds: `build-env` (build environment, no source change), `bitrot` (dead URL or vanished host tool), `bug`, `closed-replacement` (stands in for a closed Apple binary). Upstream names the later Apple release with the same fix, or "none".
