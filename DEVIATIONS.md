# Deviations

Every difference from Apple's published sources and build environment, one row each.

| ID | Project | Kind | Change | Error it fixes | Upstream |
|---|---|---|---|---|---|
| D1 | all | `build-env` | Each source tarball from Apple's GitHub is unpacked and its top folder renamed from `<project>-<project>-<version>` to `<project>-<version>`, then placed in the build folder's `Sources/`, where darwinbuild takes a plain folder. Contents unchanged. | darwinbuild looks for `Sources/<project>-<version>`; GitHub names the folder after repo and tag. | none |
| D2 | darwinbuild | `bitrot` | The nine Darwin 9 build lists are copied into the build folder's `.build/` before `darwinbuild -init`, which then finds them instead of downloading. darwinbuild itself is unchanged (`Darwin9` branch at `4848b7f`). | The default list site `svn.macosforge.org` no longer exists. | none |
| D3 | Roots | `build-env` | Where archive.org has no Root at a project's 9L30 version, the build environment gets the Root of the nearest earlier build (`older` in `manifest/9L30-roots-used.tsv`), as darwinbuild itself does. Bootstrap only: those projects are then built from source. | darwinbuild stops with `could not find root`. | none |
| D4 | file_cmds | `build-env` | The OpenSSL 46.11 Root is unpacked into the build environment before building file_cmds: libmd's headers include `<openssl/*.h>`, and file_cmds' dependency list lacks OpenSSL. | `/usr/local/include/md5.h:5:25: error: openssl/md5.h: No such file or directory` | none |
| D5 | shell_cmds | `build-env` | launchd's headers are built from source with `darwinbuild -headers -target=launchd_libs launchd_libs` and copied to `Headers/launchd/launchd-258.25.hdrs~1`, so shell_cmds' `launchd` header dependency finds them. darwinbuild passes the build list's target only for `install`, and archive.org has no `launchd.hdrs`. | `nohup.c:60:19: error: vproc.h: No such file or directory` | none |
| D6 | all | `build-env` | [env/arch](env/arch), which prints `ppc`, replaces the build environment's `/usr/bin/arch`. system_cmds' Root ships it as a `uname -m` script, which prints `Power Macintosh` on PowerPC and breaks `mig`. Until system_cmds is built from source. | `gcc-4.0: Invalid arch name : Power` | none |
| D7 | all | `build-env` | darwinbuild copies the host's `dsymutil` (Xcode 3.1.4, `dwarfutils-70`) into the build environment, where it crashes on every binary; on the host it works. The copy is renamed `dsymutil.real` and [env/dsymutil](env/dsymutil) takes its place: it runs the real one and, if that fails, puts a copy of the input binary (thinned to `--arch`) where the DWARF file would be, so later steps that copy or `lipo` it still work, and exits 0. Only the separate debug-symbol bundles are affected, never the built binaries. | xnu: `Bus error /usr/bin/dsymutil --arch=ppc …/mach_kernel.sys`, `make[2]: *** [do_build_mach_kernel] Error 138`; with an empty `.dSYM`, `lipo: can't open replacement file: …/mach_kernel.sys.dSYM/./Contents/Resources/DWARF//mach_kernel.sys` | none |
| D8 | copyfile | `closed-replacement` | [env/quarantine.h](env/quarantine.h) goes into the build environment's `/usr/local/include`. It holds the same do-nothing stubs that copyfile itself uses when built for embedded targets, plus `qtn_file_init_with_path` and `qtn_file_init_with_data`, which copyfile also calls. Apple's quarantine library is closed and absent, so Libsystem leaves it out (`CONDITIONALLIBS = unc quarantine`) and copied files keep no quarantine information. | `copyfile.c:48:24: error: quarantine.h: No such file or directory` | none |
| D9 | Libinfo, UserNotification | `build-env` | project_makefiles 126 is built from source and its Root copied into the build environment. Both projects use the old Project Builder makefiles, which call `/usr/lib/ofileListTool` and `/usr/lib/fastcp` from project_makefiles, but neither lists it as a dependency. | `make[1]: /usr/lib/ofileListTool: Command not found`, `make[1]: /usr/lib/fastcp: Command not found` | none |
| D10 | mDNSResponder, IOKitUser | `build-env` | The 9G55 `CarbonHeaders` Root (CarbonCore's headers, including `MacTypes.h`) is unpacked into the build environment. No source exists for this version: GitHub has only CarbonHeaders 18.1 and Apple's 10.5.8 release page does not list it. Headers only, used to compile; nothing from it goes into the boot volume. | `SecBase.h:63: error: syntax error before 'SecKeychainAttrType'` | none |
| D11 | mDNSResponder | `build-env` | Built with `darwinbuild -target=SystemLibraries mDNSResponder`, the Xcode target that makes only `libdns_sd.a` (with its debug and profile variants) for Libsystem. The build list names no target, so darwinbuild builds the whole project, whose daemon includes Security's headers; those need `OSType`, which the open-source CoreFoundation headers in the build environment leave undefined. The daemon is built later. | `SecBase.h:63: error: syntax error before 'SecKeychainAttrType'` | none |
| D12 | Libc | `closed-dependency` | [patches/Libc-498.1.7/0001-no-plockstat.patch](patches/Libc-498.1.7/0001-no-plockstat.patch) turns off `FEATURE_PLOCKSTAT` for MacOSX, as Libc's own iPhone platform file does; the pthread code then uses its built-in empty probe macros. With the probes on, Libc runs `dtrace -h` and the final link of libSystem loads `libdtrace.dylib`; both need Apple's closed Foundation, Symbolication and full CoreFoundation, which the build environment lacks. Libc's 18 plockstat probes are the only dtrace probes in libSystem's parts. `scripts/stage-sources` applies the patch when unpacking. | `dtrace`: `dyld: Library not loaded: …/Foundation.framework/Versions/C/Foundation`; Libsystem: `ld: couldn't dlopen() /usr/lib/libdtrace.dylib: … Library not loaded: …/Symbolication.framework/Versions/A/Symbolication` | none |
| D13 | Libsystem | `closed-replacement` | Libsystem links `-lsandbox`, Leopard's closed sandbox library, which the build environment lacks. [replacements/sandbox/](replacements/sandbox/) is a new stub with the same seven exported symbols (`sandbox_init`, `sandbox_free_error`, the five `kSBXProfile…` profile names) and a `sandbox.h`; `sandbox_init` always fails with `ENOTSUP` and an error message, so no program believes it is sandboxed. Its `build` script runs inside the build environment and makes `libsandbox.a`, `libsandbox_debug.a` and `libsandbox_profile.a` for ppc, ppc64, i386 and x86_64, which are copied with `sandbox.h` into the build environment. | Libsystem: `-lsandbox` in `LIBS`, no `libsandbox.a` in `/usr/local/lib/system` | none |
| D14 | Libsystem | `build-env` | Our Roots of mDNSResponder (`libdns_sd`), launchd_libs (`liblaunch`), Libc_debug and Libc_profile are copied into the build environment before Libsystem is built: Libsystem links them, but its dependency list names none of them, so darwinbuild would leave Apple's archived copies in place or none at all. | `lipo: can't open input file: /usr/local/lib/system/libc-partial_debug.a (No such file or directory)` | none |

Kinds: `build-env` (build environment, no source change), `bitrot` (dead URL or vanished host tool), `bug`, `closed-replacement` (stands in for a closed Apple binary), `closed-dependency` (a feature turned off because it needs closed Apple code). Upstream names the later Apple release with the same fix, or "none".
